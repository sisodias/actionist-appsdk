What we learned

Current synthesis from the research packet. Exact records and complete source artifacts remain visible below.

Research conclusions

  • Persist typed edit intent instead of only code or DOM mutations.
  • Use denial-by-construction and record accepted, rejected and refused operations.
  • Puck shows field-level write authority can live in persisted data and survive upgrades.

What it owns

  • Live preview
  • Chat and direct-manipulation edits
  • Module add/remove/replace
  • Text/content and layout changes
  • Change plan, diff and undo

Open first-principles questions

  • Which edits are parameter changes versus code changes?
  • How does the editor preserve block upgradeability?
  • What is the undo/version model?
  • How are unsupported requests explained?

Inputs

  • AssemblyPlan
  • Running preview
  • Client instructions

Outputs

  • ChangePlan
  • UpdatedBindings
  • BoundedDiff
  • Version

Explicit holds and blockers

  • Account-wide usage limit terminated survey wave 1 across all six subagents; BLOCKED not FAIL.
  • Commercial/OSS denominator shortfalls recorded per survey; no padding.
