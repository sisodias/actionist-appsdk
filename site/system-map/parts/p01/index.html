What we learned

Current synthesis from the research packet. Exact records and complete source artifacts remain visible below.

Research conclusions

  • Discovery state should be deterministic and server-owned; the model owns phrasing, not truth.
  • Score access persistence and content sensitivity separately.
  • Use explicit qualify, prototype, disqualify and escalate terminal states.

What it owns

  • Known client/account context
  • Business links and bounded site reconnaissance
  • Stakeholders, systems of record and constraints
  • Conversation history and unresolved discovery questions

Open first-principles questions

  • Which Actionist client fields are canonical?
  • What may be scraped automatically?
  • How do we distinguish stated wants from observed workflow pain?
  • What confidence threshold triggers a follow-up question?

Inputs

  • Actionist account profile
  • Client URLs
  • Conversation
  • Existing tools

Outputs

  • ClientContext
  • DiscoveryGapList
  • CandidateOutcomes

Explicit holds and blockers

  • Canonical ClientContext field set cannot be closed: depends on P02 minimum-spec (sufficiency) and P12 input contract (necessity), both unsettled in Sprint 1.
  • Rung-0 Actionist-account source blocked on the unknown Actionist data/auth contract (U in current research).
  • Scraping permission is a policy-owner decision, not a research finding; the lane can supply an auditable scrape log but not permission.
  • Per-rung, per-industry acceptance rates unmeasurable without engagements.
  • bupaR licence UNCONFIRMED (LICENSE file names no licence); must be read from DESCRIPTION before relied on as the permissive escape from pm4py AGPL.
  • Fetch-verified fraction is 29% of external rows; both commercial agents hit usage limits mid-sweep.
