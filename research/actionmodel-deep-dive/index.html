01 / decision frame

What this means for us

public-source readout

The opportunity is real enough to investigate, but the public material is still a mix of polished product surfaces, movement-style narrative, incentive-led growth and unverified milestone claims.

Why it is interesting

  • ActionFi offers partners a “real usage rather than vanity engagement” proposition.
  • Actionist gives the ecosystem a clearer SaaS monetization path.
  • GUI-action data could be strategically valuable if consent, quality, privacy and retention withstand technical review.

Where the story is soft

  • 500K+ users, extension installs, training hours and partner numbers use different definitions.
  • Illustrative dashboard values and creator-income/ROI examples are not audited evidence.
  • Current Actionist pages and older docs disagree on maturity and roadmap state.

What we must not overclaim

  • The extension has a sensitive browser-permission surface.
  • The 4.9/398 rating is not the same as 398 independently verified reviews.
  • Every social post/profile/review was not fully enumerated in this pass.

Company thesis

Action Model argues that GUI-action data is the scarce input for useful computer-use AI and that ownership should be distributed to contributors rather than concentrated in Big Tech. The blog/content system uses AI displacement and ownership framing to drive community participation.

04 / product surfaces

What they are actually building

The product read is intentionally split into user utility, partner value and diligence surface.

Training extension / LAM

The Chrome extension is described as passive opt-in browsing, workflow recording and anonymized action-data contribution. Docs describe screenshots/regions, clicks, navigation, timing, DOM and selected context as possible training inputs, while excluding credentials, payment data, private messages, raw form input, files and clipboard.

Risk: the public permission surface is broad enough that implementation behavior must be tested, not inferred from policy language.

Security/privacy docs ↗ · Chrome listing ↗

ActionFi

ActionFi is the partner bounty/verification layer: a user performs an action on a partner platform, Action Model verifies the activity and rewards the user with points, `$LAM`, partner tokens or stablecoins depending on the campaign. The differentiator is “real usage” instead of vanity engagement or API-only events.

Risk: “verified” needs a technical definition covering identity, replay/farm detection, disputes, evidence and payouts.

ActionFi docs ↗ · SDK docs ↗

Actionist

The current product site presents AI employees that use apps, run on schedules, return work for approval and expose history/transcripts. It shows a free local desktop mode and paid cloud execution.

  • Desktop: free, one agent per device, stops when laptop closes.
  • Basic: $55/month; 1 seat, 5 agents, 5GB, 1,000 reactions.
  • Pro: $155/month; 2 seats, 20 agents, 15GB, 5,000 reactions and 10h cloud browser.

Current site ↗ · Pricing ↗ · Demo ↗

Marketplace + agents

Public docs claim 10,000+ workflows and distinguish reusable workflows from full agents with memory, personality, decision-making and schedules. Examples show `$LAM` subscriptions, pay-per-action and lifetime purchases.

Risk: creator earnings, ROI examples and marketplace numbers need payout/usage exports rather than marketing examples.

Token and reward mechanics

Docs describe `$LAM` as action fuel, contributor/ActionFi reward currency, marketplace/creator utility and part of a burn/ecosystem loop. One token page uses `$0.01/action`; another formal model uses `$0.10/action`.

Open: canonical contract, TGE status, supply/allocation, token audit, treasury, unit economics and price model.

The Actionist browser-extension documentation and current FAQ are not aligned. This may be documentation drift, but it must be resolved before a client-facing maturity claim.

05 / reputation and trust

Reviews: positive signal, low independence

398 aggregate / subset read

We captured the rating/count and public review themes, but not every individual review record. The right interpretation is “strong community sentiment with provenance to investigate,” not “398 independently validated customer reviews.”

Official store

4.9/5 · 398 ratings · 80,000 users · v0.30.0 · updated 3 May 2026. The store declares user activity and website content handling.

Open Chrome Store ↗

Visible review themes

Positive: easy setup, low perceived CPU/RAM, passive training, points/rewards, privacy and community. Mixed: slow points, bugs, dashboard/activity visibility, site coverage and early-stage feel.

Extpose shows a large same-day cluster of short/generic reviews. That warrants provenance analysis but does not prove reviews are fake.

Extpose mirror ↗

Independent-ish community signal

Krain shows Action Model AI at 4.7/5 from 15 reviews. The qualitative feedback asks for audit trails, deterministic limits, benchmarks, safety/fail-safes, ambiguity handling and integration clarity.

Krain page ↗

What a complete review scrape would contain

A proper next pass should export every review ID, rating, timestamp, text, reply, author metadata where permitted, version, country/language, helpfulness and whether the account was eligible for a referral/quest/ambassador reward. Then join that data to campaign dates. Until then, keep “398 ratings” and “398 reviews” separate.

10 / next research wave

What we should do next

requires access / exports

The next steps should close the evidence gaps in order of risk, rather than simply collecting more public posts.

  1. Get authenticated social/review exports.
    Capture X, LinkedIn, Telegram, Instagram and TikTok with post IDs, timestamps, text, media links, engagement, replies and campaign labels. Export every Chrome review with stable IDs and metadata where permitted.
  2. Run a disposable-profile extension audit.
    Install the current Chrome version, diff the manifest, inspect content scripts, test pause/opt-out/masking, record outbound requests and verify synthetic secrets never leave the profile.
  3. Request the company evidence pack.
    Ask for legal entity, privacy/DPA, subprocessors, security audits, token contract/TGE, KPI dictionary, user/reward ledger, ActionFi anti-fraud report and current Actionist release matrix.
  4. Build a review and growth provenance model.
    Join ratings/reviews to referral, quest, ambassador, extension-update and campaign dates. Separate organic usage, incentivized activity, partner campaigns and product feedback.
  5. Benchmark Actionist against real workflows.
    Test 5–10 representative tasks with success rate, intervention rate, latency, failure modes, approval gates, prompt injection and cross-app data boundaries.
  6. Turn the findings into a client opportunity map.
    Prioritize trust center/privacy communication, KPI instrumentation, partner case studies, support/review loops, workflow safety UX and credible proof-led content.

What I can complete with access

With an authenticated browser session or exported data, I can turn the partial rows above into a dated, machine-readable archive: all profiles, all available posts, every review record, transcripts, engagement tables and a provenance score for each signal.

What cannot be solved by more public searching

Private Discord content, private SDK/package access, backend data retention, token/legal status, true user activity, extension network behavior and security posture require the company, a sandbox account or a technical audit.
