**Packet:** `AGENT_PACKET v1` — `SAAS-CATALOGUE`  
**Objective:** maintain a laptop-first and public-source catalogue of substantial SaaS products, clones, and self-hostable systems relevant to Action Model standardization.  
**Observed:** 2026-08-26 (Asia/Ho_Chi_Minh)  
**Mode:** read-only research. Source repositories, services, credentials, and deployment state were not changed. This report is the requested research output.  
**Current milestone:** `local-estate-inventory`, `public-map`, and `final-priority` complete; catalogue remains maintainable with explicit follow-on proof gates.  
**Evidence posture:** a local README, manifest, package file, receipt, or git record proves that an artifact exists and what it claims. It does not prove that the artifact is currently running, production-ready, legally cleared for redistribution, or an implemented Action Model capability.

## Executive state

The laptop contains several substantial, source-available systems and three unusually valuable host-assimilation efforts:

1. `SISOCRM` is a reusable CRM/internal-business-platform shell with pinned Plane, Teable, AFFiNE/SISO Docs, and SISO Notes backend material. It is still a shell/research platform, not a production-authorized generic CRM.
2. `siso-inbox-chatwoot`, `siso-engagement-listmonk`, and `siso-event-ticketing` retain large upstream applications and add explicit SISO mount, identity, database, and verification seams. They are the strongest local evidence for whole-system reuse behind a host contract.
3. `siso-docs` plus `siso-notes-backend` preserve a complete AFFiNE web client and a separate backend fork. This is the clearest local Notion/Miro-like system, but its browser/client proof is stronger than its collaborative production deployment proof.

The estate also contains reusable assembly and provenance infrastructure (`siso-ui-base`, Great Library, AutoSaaS, and the Block Contract), plus client-specific systems such as DISPO, Kellman automations, and the Bykonz/Instatic pilot. These are valuable inputs, but they are not interchangeable full SaaS products.

No record below upgrades an Action Model claim to `authenticated`, `implemented`, or `admitted block` unless the cited local receipt directly proves that narrower fact. The current Action Model long-run tracker still records zero admitted end-to-end blocks and zero authenticated/live platform dossiers.

## Classification vocabulary

| Label | Meaning in this catalogue |
|---|---|
| `whole-system candidate` | A substantial product with its own application/runtime/data shape; may be adopted behind an explicit boundary. |
| `adapted host module` | A whole upstream application retained locally with a tested or documented SISO mount/identity/data seam. |
| `platform bundle` | A host plus multiple donors/modules; useful as an architecture candidate, not one licensable code unit. |
| `bounded reusable source` | A framework, bridge, scaffold, or vertical slice with a narrow reusable contract; not a full SaaS. |
| `reference-only` | Readable evidence or a product-shaped prototype whose source, license, maturity, or boundary is not sufficient for reuse. |
| `unknown` | The local material is real but does not establish enough about maturity, ownership, or license to choose a reuse mode. |

`Reuse mode` is an engineering disposition, not legal advice. A declared SPDX/MIT/AGPL label is recorded as source evidence; it is not a complete dependency, asset, enterprise-edition, or commercial-license clearance.

## Boundary that must not be lost

The strongest local result is **not** “SISO already has arbitrary SaaS standardization.” It is:

```text
source-owned product or donor
  → explicit host/module contract
  → namespaced identity + database + cache boundary
  → route/lifecycle preservation
  → build/API/browser/negative-permission evidence
  → human admission with provenance, ownership, and rollback
```

Chatwoot and listmonk have the most complete adapted-module receipts. Hi.Events has a strong backend journey but host and object-storage seams remain. AFFiNE/SISO Docs has the strongest complete client surface but a pending interactive browser and collaborative-production gate. Teable and Plane are significant donor systems with mixed/c/copyleft license boundaries. These are reusable systems and reference points, not proof that one arbitrary product can be standardized automatically.
