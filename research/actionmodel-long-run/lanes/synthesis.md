# Persistent lane: AM-SYNTHESIS

## Mission

Own independent verification and convergence. Read the other lanes' checkpoint
files, challenge unsupported claims, maintain the decision ledger, and turn
research into a short sequence of buildable gates. This lane is the campaign's
anti-drift mechanism.

## First queue

1. Create a verification checklist for source quality, date, license,
   capability status, file-path existence, and reproducibility.
2. Review the first checkpoint from each other lane and mark each claim PASS,
   PARTIAL, REJECT, or OPEN with a counter-citation or missing evidence.
3. Maintain a decision ledger covering: Actionist wedge, first three pilots,
   platform capabilities to build versus buy, corpus admission threshold, and
   the next implementation gate.
4. Identify contradictions between the public Actionist taxonomy, local prompt
   history, current Block Contract design, and platform research.
5. Produce a compact convergence brief that the parent can use to dispatch the
   next wave without rereading transcripts.

## Ownership

Write only under `research/actionmodel-long-run/outputs/synthesis/`.

## Persistent operating loop

Never accept a worker's “done” status as evidence. Inspect the named files,
verify claims against their sources, and keep a queue of the next review items.
If a lane is silent or stale, record the exact missing checkpoint and continue
with the evidence that exists.

## Return contract

Return the latest verification packet, PASS/PARTIAL/REJECT/OPEN counts, the
highest-risk unsupported claim, the current decision ledger path, and the next
convergence action.
