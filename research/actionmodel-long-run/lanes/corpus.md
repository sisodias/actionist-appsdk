# Persistent lane: AM-CORPUS

## Mission

Own the local GitHub/OSS intelligence and admission pipeline. Turn the existing
repo pile into a ranked, reproducible supply chain for reusable Action Model
blocks. Do not chase an impressive repository count; prove which candidates can
survive adaptation, licensing, build, browser smoke, and client ownership.

## First queue

1. Reconcile `research/github-sweep/` into capability clusters and identify
   duplicates, stale candidates, missing metadata, and high-value untouched
   areas.
2. Define the candidate-to-block evidence ladder: canonical URL/commit,
   license/provenance, stack/runtime, routes/components/schema/auth/data
   boundaries, adaptation notes, build/typecheck, browser smoke, screenshot,
   owner, rollback, and tenant/deployment assumptions.
3. Rank candidates for three pilots: a read-only client dashboard, a
   document/finance workflow, and an operations or CRM workflow.
4. Inspect the local Awesome catalogue and any mounted corpus before widening
   to direct GitHub search. Record missing data planes as blockers rather than
   filling them with guesses.
5. Produce one candidate admission packet that can be handed to a worker for a
   real Block Contract conversion.

## Hard boundaries

- A repo is not a block until its admission evidence exists.
- GPL/AGPL or unclear licensing is a hold/reject decision, not a casual reuse.
- Do not modify or reformat the 389-candidate merged artifact in place.
- Preserve existing user/agent changes and write new analysis under this lane.

## Ownership

Write only under `research/actionmodel-long-run/outputs/corpus/`.

## Persistent operating loop

Process one cluster or admission packet at a time. Every checkpoint must state
the candidates reviewed, accepted/held/rejected counts, evidence paths, and the
next bounded queue. Keep going after the first report; the lane is a standing
intelligence and admission function.

## Return contract

Return the latest checkpoint path, candidate counts by disposition, the best
pilot candidate, the strongest rejection reason, and the next queue item.
