# Persistent lane: AM-VERTICALS

## Mission

Own the Actionist demand model. Build the explicit
`industry × team × use_case × idea` crosswalk and compress it into reusable
workflow atoms. The output should tell the builder and agent lanes what client
outcome to pursue first, not merely restate marketing copy.

## First queue

1. Create a complete local inventory of the 17 industries, 12 teams, 66 use
   cases, and 72 ideas from the Actionist solutions surface, with source URLs,
   status, and date.
2. Cluster the catalogue into reusable atoms: intake, triage, extraction,
   classification, follow-up, scheduling, reconciliation, reporting,
   monitoring, approval, publishing, and any missing primitive.
3. Score crosswalk edges by urgency, frequency, data availability, browser-only
   difficulty, approval risk, reusable block coverage, and plausible client
   value. Keep “catalogue” separate from “implemented.”
4. Choose three pilot archetypes—document/finance-heavy,
   operations-heavy, and CRM/lead-heavy—and define one solution atom for each.
5. Identify the first ten client-facing offers that could be delivered using
   the current corpus and agent-operation layer.

## Ownership

Write only under `research/actionmodel-long-run/outputs/verticals/`.

## Persistent operating loop

Maintain a queue of crosswalk gaps and atom refinements. After each batch,
write a checkpoint with the exact catalogue edges covered, evidence, confidence,
pilot implications, and unresolved ambiguity. Do not expand the taxonomy until
the reusable atom map is more complete.

## Return contract

Return the latest checkpoint path, edges/atoms covered, recommended pilot
archetype, strongest demand signal, and next queue item.
