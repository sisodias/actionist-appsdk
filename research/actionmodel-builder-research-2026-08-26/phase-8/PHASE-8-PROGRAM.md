# Phase 8 — Universal Block Foundry research sprint

Status: active, unpromoted research  
Date: 2026-08-27  
Coordinator: CENA  
Model policy: five persistent Claude Opus 5 lanes, one deliverable owner per lane

## Objective

Design the missing system between the existing research corpus and a Lovable-like product:

`repo/local asset → evidence-backed reusable block → governed registry → agent-composed B2B application`

The goal is not another broad repository count. The sprint must join the existing Block Contract, AutoSaaS harvest policy, Great Library provenance, SISOCRM transplant/module contracts, `siso-ui-base` visual pipeline, 17-industry taxonomy, and public OSS evidence into one falsifiable framework.

## Existing Opus work that must not be duplicated

1. Connector Opus is actively researching Activepieces, Composio, Nango, MCP registries, OAuth/token vaults, and embedded connection UX.
2. Lovable-clone Opus has already extracted 38 builder-class repositories from the 500-repo corpus and classified reuse boundaries.
3. Template Opus established that the pack has a vertical taxonomy and raw starter lanes but no curated deployable B2B template shelf.

## Five disjoint lanes

| Lane | Owns | Must produce |
|---|---|---|
| 01 Universal block framework | Canonical architecture and contracts | Framework report, block lifecycle/state machine, universal contract delta, cross-system mapping |
| 02 Local corpus join | Laptop assets and exact metadata | Local asset register, dedupe/overlap map, rights/readiness gaps, recommended joins |
| 03 B2B template shelf | App-level starters for the 17 industries | Archetype taxonomy, source candidates, template contract, prioritized shelf |
| 04 Repo-to-block mechanics | Conversion/extraction mechanisms | Tool/evidence census, deterministic pipeline, negative paths, proof receipts |
| 05 Composition agent and evals | Retrieval, planning, composition, cost and evaluation | Agent architecture, graph/retrieval contract, eval suite, synthetic pilot and economics |

## Convergence invariants

- Every major claim must cite a local path or first-party URL and label direct, inferred, gated, or unknown evidence.
- Repositories are not blocks. A candidate becomes a block only through explicit identity, provenance, rights, dependency, interface, data, visual, runtime, maintenance, rollback, owner, and evaluation evidence.
- Local component counts, repository counts, and repeated metadata observations never substitute for capability or admission proof.
- The 17 industries are a demand and composition denominator; shared archetypes/atoms should reduce duplicate implementation.
- The final framework must support both intact packages/services and bounded extracted slices, with reference-only as a valid outcome.
- Each lane writes only inside its own `phase-8/lanes/<lane>/outputs/` directory.
- No client data, authenticated vendor actions, cloning/copying source, source execution, implementation, deployment, benchmark, license scan, or block admission.

## Promotion gate

Phase 8 remains unpromoted until all five lane artifacts exist, callbacks are verified, an independent cross-lane contradiction pass is run, and the coordinator writes a synthesis that explicitly preserves unresolved rights, runtime, economics, and client/legal gates.
