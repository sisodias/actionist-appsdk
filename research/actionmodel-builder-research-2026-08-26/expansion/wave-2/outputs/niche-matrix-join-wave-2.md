| State | Meaning | Allowed evidence | Explicitly not implied |
|---|---|---|---|

| `unobserved` | Ledger slot has no selected receipt yet | Explicit JSONL slot record | Negative demand, broken market, or lack of solution |
| `blocked_pending_receipt` | A cell cannot pass its next gate because an exact source, authority, rights, eval, or runtime receipt is missing | Gap code plus next gate | “No solution exists” |

### 2.3 Evidence classes

`E` = directly inspected local artifact, repository record, standard/spec, or first-party source; `D` = documented first-party claim not independently authenticated; `I` = inference/priority/mapping from multiple sources; `U` = unknown or unverified. A cell can contain several classes; the weakest unresolved gate remains visible.

## 6. Thin, blocked, contradictory, and unserved cell rules

- Thin means n > 0 and n < 10. All 750 observed slots are thin at the cell level.
- Unobserved means n = 0. The ledger has no selected receipt for that exact industry/dimension. This is not evidence that the industry has no data model, workflow, or demand.
- Blocked pending direct source means n = 0 with cell_state blocked_pending_direct_source. The blocker is a missing exact receipt/inspection, not market absence.
- Contradictory means the catalogue remains 66/72 while a derived crosswalk reports 39/24; both are retained with source labels.
- Unserved/no-seed means G-NO-SEED: no current repository observation was assigned to the cell. It must be followed by bounded search and access-limit receipts.
- Capability gap means a documented commercial primitive or generic repository may be useful evidence while still failing exact domain, authority, rights, eval, runtime, or maintenance gates.
