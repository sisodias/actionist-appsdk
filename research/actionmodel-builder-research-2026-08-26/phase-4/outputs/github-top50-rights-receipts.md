### Interpretation rules

- A repository URL is an identity and access boundary, not proof that the URL was reachable in this lane.
- A README or description string is a first-party documented claim; it is not authenticated behavior, adoption, retention, or production evidence.
- A declared permissive license signal is not rights clearance. SPDX is recorded or NOASSERTION when absent; no legal conclusion is made.
- Stars, forks, issue counts, timestamps, and archived flags are maintenance metadata only; they do not establish health, support, security, or reliability.
- Matrix, industry, and dimension joins are ranking context. They do not establish capability, demand, implementation, or safety.
- Every candidate remains reference_only and not_admitted until the recorded clean-room gate is authorized and completed.

## Normalized receipt contract

Every JSONL line and every ledger row carries the following receipt families:

- identity: receipt ID, priority ID, rank, score/band, owner/name/URL/default branch/identity key;
- joins: industry fit IDs and basis, matrix evidence class/count/cells/slots, and target cells;
- public metadata: evidence class, sponsorship/source class, description claim, four recorded public metadata URLs, reachability and README boundaries;
- rights: declared license state, repository API signal, root license-file signal, SPDX or NOASSERTION, rights status, and provenance unknowns;
- maintenance: state, stars, forks, issues, archive flag, update/push dates, age, and metadata score;
- dependency/SBOM: exact recorded status and manifest signals, with no scan performed;
- disposition: original candidate/hold value plus explicit reference-only and not-admitted boundary;
- falsifier and next clean-room gate: original Phase-3 falsifier and ordered next-gate actions;
- retention and research boundary: correction route, access limits, UNEXECUTED, NOT_ADMITTED, implementation false, and no external side effect.
