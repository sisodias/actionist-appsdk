# Action Model Builder — Phase 4 source evidence and pilot readiness

Run: actionmodel-builder-research-2026-08-26  
Phase: source-depth-and-pilot-readiness  
Status: dispatched; parent research goal active  
Predecessor: Phase 3 coordinator-verified with five lane receipts and eight artifacts  
Mode: research only; no implementation, execution, deployment, client data, vendor login, or admission

## Purpose

Phase 3 produced the ranked queues and the falsifiable synthetic pilot design.
Phase 4 turns the highest-value queues into attributable evidence and a more
operational receipt plan. It is still a research phase: an HTTP response is
reachability, a README is not a capability proof, a license signal is not legal
clearance, and a pilot runbook is not pilot authorization.

## Non-negotiable boundaries

- No vendor login, paid plan, private contract, client data, production account,
  credential, or authenticated behavior test.
- No repository clone, source-code copy, arbitrary source execution, build,
  deployment, external write, payment, or admission decision.
- Public first-party pages may be read for source evidence only where a lane
  explicitly permits it; gated, stale, contradictory, and inferred evidence
  must remain labeled.
- Local corpus work is restricted to inventory-listed metadata and named
  manifests. Do not open arbitrary source files or execute local tooling.
- Rights, SBOM, security, runtime, cost, maintenance, and client/legal claims
  remain unknown or unexecuted unless a receipt proves otherwise.
- Each worker writes only its own Phase-4 artifact and lane object. The
  coordinator owns shared Phase-4 promotion.

## Lane contracts

### RCH-PLATFORM-P0-A

Inspect platform source-depth triage ranks 1–7 using public, first-party
documentation and product pages only. Produce one normalized record per ranked
surface with exact source URL, access/evidence date, direct claim versus
inference, missing Block Contract fields, lifecycle/access limits, falsifier,
and the smallest next read-only gate. Do not log in or infer authenticated
behavior.

Outputs:

- `outputs/platform-p0-evidence-a.md`
- `outputs/platform-p0-evidence-a.jsonl`

### RCH-PLATFORM-P0-B

Perform the same source-depth protocol for triage ranks 8–14. Keep the two
platform packets disjoint by rank and preserve the exact first-party evidence
identity. A thin or inaccessible page is a result, not permission to fill the
gap from marketing copy or inference.

Outputs:

- `outputs/platform-p0-evidence-b.md`
- `outputs/platform-p0-evidence-b.jsonl`

### RCH-GITHUB-TOP50-RIGHTS

Use the Phase-3 candidate-priority register to select the deterministic top 50
candidate records for a public metadata and rights/provenance receipt. Record
repository identity, source URL, declared license signal, SPDX/NOASSERTION
state, maintenance metadata, dependency/SBOM unknowns, source-access boundary,
and a falsifier/next gate. No clone, code copy, arbitrary source inspection,
execution, build, or reuse/admission claim.

Outputs:

- `outputs/github-top50-rights-receipts.md`
- `outputs/github-top50-rights-receipts.jsonl`

### RCH-LOCAL-CORPUS-METADATA-DEPTH

Use the Phase-3 local-corpus triage queues to perform bounded metadata follow-up
only. Read only inventory-listed paths and explicitly named manifest/readme or
package metadata; do not open arbitrary application source. For each inspected
root, record path identity, allowed metadata observed, freshness/owner/right
signals, overlap or missing state, and the next safe gate. No move, delete,
rename, network, execution, or source admission.

Output:

- `outputs/local-corpus-metadata-depth.md`

### RCH-PILOT-RECEIPT-RUNBOOK

Convert the Phase-3 `PILOT-OPS-READMODEL-001` design into a design-only runbook
that maps the seven evaluation gates and 20-task matrix to fixture IDs, receipt
fields, owners, stop conditions, and explicit authorization prerequisites.
Identify what can be run only after approval and what remains unexecuted. Do not
run a model, browser, runtime, license scan, security probe, or pilot; do not
authorize a block.

Output:

- `outputs/pilot-receipt-runbook.md`

## Shared promotion gate

paths reconcile, each evidence claim has a source or explicit unknown, all
rights/runtime/client boundaries remain intact, and the shared state still says
`implementation_authorized=false`, `execution_status=UNEXECUTED`,
`admission_status=NOT_ADMITTED`, `admitted_blocks=0`, and
`parent_goal_status=active`. Phase 4 completion does not authorize or execute
the synthetic pilot.
