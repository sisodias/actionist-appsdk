## Repeatable first-party search protocol

The protocol is designed to be rerun without silently converting search discovery into evidence. It has five bounded passes:

- **Seed:** start from the immutable 67-surface register and four category queries; do not start from vendor comparison pages or search snippets as proof.
- **Discover:** use category queries Q1–Q4, then retain only candidate identities with an official domain, official docs, official pricing/product page, or official source repository.
- **Resolve:** follow one first-party redirect, record the old/current identity separately, and canonicalize by organization + product family + official hostname/path.
- **Inspect:** open the first-party product/docs/pricing/API/source surface; record source class, observation date, HTTP/access state, explicit claims, and the exact unknowns.
- **Adversarial/dedupe:** search the official domain for API, MCP, export, self-host, tenancy, audit, rollback, support, maintenance, OEM, shutdown, and migration terms; mark gated/thin/contract-only fields U; dedupe rebrands and product families before counting.

### Exact query set used

- Q1: `official AI app builders design-to-code visual builders product docs pricing API export self-hosted`
- Q2: `official AI agent workflow automation MCP browser computer use platforms docs pricing`
- Q3: `official low-code internal tools data app builders self-hosted API deployment pricing`
- Q4: `official code agents runtimes sandboxes deployment platforms API docs pricing`

Candidate sources were directly opened after discovery. A curl HTTP probe was run against each candidate URL and against one canonical URL per existing surface. HTTP status is reachability only; it is never behavior proof.

## Evidence classes and field contract

- `E/D`: current first-party page directly inspected; documented claim, not authenticated behavior.
- `E/U`: first-party URL was reached or attempted but reader-limited, thin, redirected without parity proof, rate-limited, or otherwise insufficient for the claim.
- `I`: inference or comparison; not used as behavior proof.
- `U`: unknown because private, gated, contract-only, stale, thin, not directly documented, or not behaviorally authenticated.

Every existing record has explicit keys for prompt/design/repository input, data/auth, agent/tool authority, API/MCP, import/export, deployment, tenancy, pricing/usage, audit, portability, maintenance, support, rollback, lifecycle, OEM/white-label, unknowns, falsifier, source class, date, access limit, and source URL.

`authenticated_behavior` is explicitly `U` for every record: no vendor login, authenticated API call, generated application, deployment, production execution, or client-data test was performed.
